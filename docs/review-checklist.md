# Review checklist

The defects outside reviewers (Copilot) keep finding after our five stages pass. Build designs against it, Test writes a test per applicable row, Review walks every row against the diff. Each row names the miss that taught it.

When an outside review finds something this list doesn't cover, add a row for the general class, not the specific bug (see `.claude/commands/unit.md`, step 8).

## How to apply it

Don't read the diff top to bottom against the list. First list the stateful pieces the unit added or changed: hooks, services, components with handlers, engine listeners, mutations, migrations. Then take each piece through every row that applies. A row that applies with no test proving it is a finding.

## 1. Interleavings: what else can happen while this is in flight?

For every async window (a pending mutation, a load, a count-in, a hand-over between "told to play" and "playing"), list every user input and every event that can arrive during it, and decide what each one does.

- **Input during a pending write.** A form locks its fields while saving, but other inputs that feed the same draft keep writing to it. _08: score taps changed the loop form's range while its save was pending; success then closed the form and discarded the new pick._ Any state the write reads has one owner of the "saving" flag, and every writer checks it. An exit left open is an input too: a link, a button or a toggle beside the form that unmounts it takes the pending write's `onSuccess`, its draft, its retry id and its error with it. _PR 31: "Practise it" on the loop saved before stayed usable while the next loop's save was pending; following it lost a failed insert's draft and its message._ Lock every way out of the form while it saves (`aria-disabled` and a refusing handler where focus may be on it), not only its own fields and Cancel. Where the ways out can't all be locked (the nav, the browser's Back) and the write's state is read from a shared cache instead, so a second view can show it, everything that view draws moves there with it: the flag, the failure and what is being written. _14 QA: a recordings form opened again mid-save read "saving" from the mutation cache and its fields from the saved links, so it said "Saving…" over empty fields._ Open the second view while the first step of the write is held, and assert what its fields hold.
- **Two writes to one item.** A response from an older write must not overwrite a newer optimistic value. _08: a "Save speed" response put the old bars back over a pending range edit._ While another write to the item is pending, a response applies only the fields its own request sent, and each only while the cache still holds the value it sent. _11: offline, 90% then 80%; on reconnect the first answer put 90% back while 80% was still on its way, and a stalled second send left it there (Copilot)._ A read of the item's list that starts while the write is pending is an older answer too: the library's own refetches (window focus, reconnect, a screen mounting the list) run during a write's retry backoff. _Bug hunt: a bars edit waiting to retry was undone by the refetch on focus, moving the playing loop back._ Hold those refetches while a write of the item is pending.
- **Late events after a user's halt.** Events already on their way (from a worker, a timer, the network) arrive after pause, stop, unmount or a seek. _07: `pause()` then a late `finished` restarted the count-in._ A user's halt is latched until the next explicit start, and every event handler that starts or moves something checks it.
- **Hand-overs.** Between "told the engine to do X" and "the engine reports X", every cancel path must undo X too. _07: `setRange()` in that gap left playback running under a `ready` snapshot._ And the report of an X that was undone still arrives: it must not act on what was started since. _Bug hunt: "Play loop" on another loop just after a count-in's downbeat; the first play's late "playing" ended the new count-in, and the press did nothing._ Code that hides a stop-and-start of its own from the listener must still pass on the report the listener is waiting for. _Live metronome, Copilot: a voice change just after a count-in's downbeat hid the restart's "playing", so audio ran while the service stayed counting in._
- **Asked before it can be done, then forgotten.** A call that is a no-op until something has loaded (a scroll before the song is ready), made from an effect that won't run again once it has, is lost without a word. _Bug hunt: a loop opened by `?loop=` while the soundfont loaded was never scrolled to._ Keep the request and do it when the thing is ready, or re-run the caller on readiness. "Ready" can be several things that finish in either order: keep the request until the one that does it says it could. _Bug hunt, Copilot: the sounds came in before the notation had rendered, the scroll had no bounds to use and the request was dropped anyway._
- **Every tab hears it.** Some events reach every open tab of the app: a service worker taking over, storage and BroadcastChannel messages, IndexedDB shared by all of them. A default that acts on such an event acts in tabs where nobody pressed anything, and a tab's view of "pending" misses another tab's. _Bug hunt: "Reload to update" in one tab reloaded another mid-practice (vite-plugin-pwa reloads on `controlling` without `onNeedReload`); sign-out in one tab emptied the outbox another tab was still sending._ Say what each other tab does, and read shared state, not this tab's copy of it.
- **What counts as a refusal.** A queued write that is dropped (rolled back, its outbox entry deleted) on any coded error drops it for errors that are about the request's credentials, not its content. _Bug hunt: a token that expired while a "Save speed" waited offline came back as PGRST303 and the edit was lost._ List the codes that mean "try again" (network, expired token) beside the ones that mean "no", and make sure a retry changes what was refused: a retry of a refused token must send a new one. _Bug hunt, Copilot: supabase-js refreshes only a token whose stored expiry is near, so a token refused for a bad signature went again unchanged at every retry and held up the queue behind it._
- **A lost answer is an unknown outcome.** After a write that failed for the connection, the server may have done it, or may still be doing it: a read made afterwards that finds nothing doesn't prove it never will (the insert can still be running, or commit after the read). _13, Copilot: `uploadSong` looked the row up after a lost insert answer and removed the file when the look-up was empty, so an insert still running then would leave a listed song with no file._ Treat "found nothing" like "couldn't look": undo only what a late success can't leave broken, keep the rest, and say the outcome is unknown. Write down which leftover each choice risks (here an orphan file, which blocks nothing, against a song that can't play).
- **Done once, on cached data.** Something a page does once (open the item a link names, pick a default) that reads a query's `data` runs against whatever was cached before the page opened, and its "handled" latch then ignores the fresh list. _09: `?loop=<id>` was settled against a loops list cached from an earlier visit, so a loop saved on another device never opened and an edited one opened at its old speed._ Latch only on a read made since mount (`isFetchedAfterMount`), or on one that failed or is paused; and say what a late answer does if the user has acted meanwhile.
- **Older work that joins a queue late.** Work an earlier page left (a replayed outbox entry) is queued only once an async read has answered, behind anything the user did meanwhile, so the older value reaches the server last and wins. _11: a "Save speed" made before the outbox was read was undone by the replay of an older speed._ Drop from the old work what newer work has set, or hold the new work until the old is queued; and keep the old work's original time when it is queued again.
- **Saved on a timer, lost on exit.** State persisted on a throttle or debounce (a cache written a second after a change) misses the last change when the page is hidden or closed first; restore-then-replay done in the wrong order puts the older copy back. _11: a loop saved and the phone locked within a second opened offline with no loop._ Write at once on `visibilitychange` to hidden and on `pagehide`, and start anything that changes restored state only once the restore is over.
- **A refetch that fails over data.** A failed background refetch keeps its data but sets `status` to `error`, so anything that decides from `status` or `isError` whether there is something to show, keep or persist throws good rows away. _11: the persisted cache took `success` queries only, so a moment's bad Wi-Fi and then an offline restart lost lists and settings already opened (Copilot)._ Ask `data !== undefined` (`isLoadingError` for "nothing to show"), and test with a refetch that failed over cached rows.
- **A wait that comes back after the start.** A condition that holds something back until it can start (a query loading, a file not in) is evaluated on every render, so it can turn true again once the thing is running, and unmount it. _11: offline the song page opened the player on default settings; on reconnect the settings query went from paused to fetching, the "loading" branch came back and the playing song was torn down (Copilot)._ Latch the decision once it has started (per item, so the next item waits again), and test the input that arrives after the start.
- **Resumed from a snapshot taken before.** Work that pauses something and later puts it back (a rebuild, a reload, a retry) restores the state it saved at the start, undoing whatever the user changed in between. _Live metronome, Copilot: a seek made while a voice change rebuilt the MIDI was undone when playback restarted from the tick saved before it._ Every input that changes the saved state while the work is in flight updates the snapshot (or the work reads the state afresh when it resumes), and a test changes it mid-flight.
- **A clamp in the database, applied after the comparison.** A trigger that keeps a value from moving back and also caps it at `now()` must cap the incoming value first: `now()` is the transaction's start, so a transaction that began earlier, capping after it compared, pulls back a later value a newer transaction already saved, even on a write that never sent the column. _14, Copilot: `songs_keep_last_played` capped `last_played_at` last, so an older title edit could move a newer played time back._ Cap what comes in, then compare with what is stored; and for a queued write whose list is read by the same screen, cancel a read already on its way, hold the list's own refetches while the write is pending, and read once when the last one settles (_14, Copilot: an in-flight Songs read put the old played time back_).
- **Effects run twice.** StrictMode mounts, cleans up and mounts again; lazy factories can both resolve. _05: two alphaTab APIs on one element; destroying the first cleared the second._ Anything an effect creates is owned by that run and is checked as current after every `await`.

## 2. Gates: does the control agree with the action?

- **Enabled when the action would refuse.** A button's `disabled` condition must be the action's own precondition, from one exported predicate, never a separate proxy for it. _08: "Play loop" was enabled on `barCount` while the player was still `loading`, so a press did nothing and also closed the sheet._ Search for every caller of the action and check that each one uses the same predicate (`isLoaded`, `isRunning`, `isValidBarRange`).
- **A stand-in for a control that isn't drawn.** A control that leads to another one (a button that opens a panel and focuses a control in it) is offered on a condition of its own, while what draws the target has more branches (a form replacing the list, a loading or error state). _12, Copilot: while a loop played, the bar's speed slider gave way to "Loop speed", but with the loop form open the panel showed the form, not the loop's speed control, so the button did nothing and there was no speed control at all._ The stand-in's condition is the target's render condition, from one exported predicate (`panelShowsLoopSpeed`), and a test opens every branch that replaces the target.
- **On before what it changes is set up.** A control that changes a value is enabled on the player or the page being there, while the thing the value belongs to (the item a link opens, with its saved value) is opened a moment later by an effect, which then sets its own value over the user's. The change is played or shown, saved nowhere, and gone. _20 batch 1: on a loop's practice screen a speed nudge made before the loop was open (as long as a hung read, 2 s once capped) was played and then replaced by the loop's saved speed._ For every wait before an item opens, list the controls that are on during it; gate each that the opening will overwrite on the item being open, with the same predicate for its key, and test a press made inside the wait.
- **Side effects of a refused action.** If the action can refuse, nothing else the handler does (closing a panel, clearing a draft, moving focus) runs when it does.
- **An action that throws away pending work.** A control that empties state (sign-out clearing the device) must not be enabled while work it would discard is still unanswered, online as well as offline. _11: sign-out was gated on the connection only, so a speed whose request hung was dropped from the outbox without a word._ Gate it on "nothing pending" from the same cache the writes live in, for every kind of write it would cut off (_bug hunt: uploads, song deletes and settings saves weren't counted, so a sign-out mid-upload left an orphan file_) and in every tab that shares what it empties (the outbox), count every way a write can leave that bypasses that cache (a keepalive fetch, a beacon) until its answer and any fallback are dealt with (_11: a keepalive session log sent from a hidden page left Sign out enabled once the page was back, Copilot_), and test the handler with a press made before the button has re-rendered (the disabled button alone never reaches it).

## 3. Gestures and event sequences: judge the whole path, not the endpoints

- **A path that returns to its start.** Drag-or-tap decided by comparing the end point with the start misses a drag that came back. _08: the drag emitted both `barsDragged` and `barTapped`._ Keep state for the whole press (did it ever leave the slop?) and carry it to the trailing `click`.
- **Points outside the visible area.** Hit-testing a window-level move against the full surface picks things the user can't see (clipped by a scroll box, under a sticky bar). _08: a drag past the score box picked hidden bars._ Reject points outside the visible client rectangle.
- **Where a click lands.** A `click` goes to the nearest element that both the press and the release were on. _10: selecting text in the shortcut list and letting go past its edge clicked the backdrop, which closed it._ A "click outside" handler checks where the press began, not only the click's target.
- **The other half never comes.** A flag set on one event and cleared by its pair (keydown and keyup, pointerdown and pointerup) stays set when the pair goes to another window or is cancelled. _10: a Space held while switching windows left "cancel the next Space keyup" set, so a later Space on the list's Close didn't press it._ Reset the flag at the start of each new first half, and say what a lost second half leaves behind.
- **Which of the browser's gestures the handler is for.** A handler for one kind of gesture hears every kind that fires the same event: `dragover` comes for a file from the desktop, a link or image dragged off the page, and selected text alike; `click` for a mouse, a tap and Enter. _12 Review: the library's "drop a file anywhere" outlined the whole list when a song card's link was dragged a few pixels._ Check what the event carries (`dataTransfer.types` includes `Files`, `pointerType`) before reacting, and test with the kinds it must ignore.
- **A copy of what the browser holds.** State that mirrors something the browser also changes by itself (which element has focus, the scroll position, the selection, an input's value) goes stale when it changes another way: a click, a tap, the browser's own scrolling. Setting the copy to the value it still holds then changes nothing and runs no effect. _12, Copilot: the "More" menu kept the focused item's index in state for its arrow keys; after a click focused another item, End to the item the keys last chose left focus where the click put it._ Read the browser's own state at the moment of use (`document.activeElement`) and act on it directly, or keep the copy in step on every way it changes (`onFocus`), and test a key after a mouse move.
- **Every event a gesture produces.** Write down the full sequence the browser fires (`pointerdown`, `pointermove`s, `pointerup`, `click`, touch vs mouse, pan cancels) and say what each does.

## 4. Round trips: does a value survive display, edit and save unchanged?

- **Rounded for display, written back rounded.** A value shown rounded, parsed back and diffed against the saved one changes data the user never touched. _08: a target of 0.855556 shown as 86% was saved back as 0.86 on a rename._ Diff on the displayed value (or the touched-fields draft) and send the stored value untouched.
- **Display rounding vs storage.** Store the exact value the user's input implies; round only for display (AGENTS.md, speed ratios).

## 5. Validated paths: is there a way around the check?

- **A shortcut gated on how the app was built, not on what it talks to.** A convenience for development (a sign-in that skips the email, a seed that sets passwords, a debug write) checked only against the build mode or "is this a script" still runs when its configuration points somewhere real: a dev server whose env names a hosted project, a seed run with a hosted URL and key. _16, Copilot: "Dev: sign in" and the seed would have given hosted accounts the shared, public dev password._ Gate it on the target too (`isLocalSupabaseUrl`, on the URL as configured), in the action as well as where its control is drawn, and decide before the first write.
- **Pages read by offset while rows are being added.** A list read in several `.range()` requests is not one snapshot: a row inserted between two requests that sorts before the offset moves every later row along, so the next page repeats one and the new one is missed. _16, Copilot: a session replayed from the outbox between two pages of the Stats read was counted twice._ Dedupe by id when the pages are joined, and say what reconciles the row that was missed (an invalidation, a cursor).
- **A cache left wrong until a refetch succeeds.** Invalidating a list after a write that removed rows from it leaves the old rows on show, counted and persisted for offline, for as long as the refetch fails or the connection is gone. _16, Copilot: a deleted loop's sessions stayed in the Stats totals and the streak._ Take the rows out of the cache in `onSuccess` (cancel a read already on its way, which is from before the write), then invalidate; test with the refetch failing.
- **A clean-up done on one shape of an input and not the others.** Input is tidied where the tidying was first needed (a link lifted out of a sentence loses the sentence's punctuation) and the same input arriving another way keeps the mess: alone, wrapped, or without a part the first shape always had. _14 QA: "see (https://youtu.be/…)." gave the video, while the same link pasted alone as `(https://youtu.be/…)` was refused and `https://youtu.be/….` was saved as a link to a page YouTube doesn't have; a title before `youtu.be/…` with no scheme was refused though the bare address alone was taken._ Do the tidying in one function every shape passes through, and write the test as a table of the same value in each shape (alone, among words, wrapped, with and without its optional parts). Removing a character is a guess, so say what makes it safe (a closing bracket only when no opening one is inside).
- **The new build on the old schema.** "Additive" proves the build that is live keeps working once a migration lands. The build that ships with the migration is the other half: a select naming a new column or a read of a new table fails whole until the migration is in, and a deploy and a migration started by the same push finish in either order. _14 Review: the Songs list's select gained `last_played_at`; deployed a minute before its migration, the first screen can't load on a cold start._ Say which screens read what the migration adds, and when one is a first screen push the migration before the build (docs/release.md), or make the read tolerate the column's absence.
- **A second entry point that skips validation.** _05: downloaded bytes went straight to `api.load`, bypassing the Guitar Pro-only `parseScore`, so a damaged file became a one-bar alphaTex score._ Every input that a check exists for reaches the code only through that check.
- **Containment that depends on where focus is.** A trap or guard attached to the element it protects only hears events from inside it, and focus can be outside without the user leaving: a click on non-focusable text puts it on `<body>`. _10: the shortcut list kept Tab on Close with a listener on the dialog; after a click on its heading Shift+Tab went to a control behind the open overlay, which could then be pressed._ Make what is behind `inert` (or use a native modal), handle the key at the document, and test from focus on `<body>`.
- **Focus when a control replaces itself.** A button whose press swaps it for something else (Edit for a form, Delete for its question, Cancel or "Keep it" back again, an item deleted) takes focus with it to `<body>`, and a keyboard or screen reader user starts again from the top. _10: "Mark finished" moving its loop to another list; bug hunt: every inline Edit, Delete and confirm in the library and the loop panel._ For each such control say where focus lands, and test it (`useFocusWhenReady`, `src/lib/itemFocus.ts`). That includes the item leaving a filtered list because of the press: the hand-over then belongs to the list, which outlives the item. _Bug hunt, Copilot: a rename saved under a library search that no longer matched dropped focus to `<body>`._ The component that holds the wait (`useFocusWhenReady` looks again on its owner's renders) must be one that re-renders on the change: one moved up a level for another hand-over stops hearing changes made below it. _13 Review: the library's hand-over moved to the page so a last song's delete could use it, and Cancel on a song's edit form, which re-renders only the list, left focus on `<body>`._ And what the finder returns must be able to take focus: `focus()` on a disabled, hidden or `inert` element does nothing, and the one-shot wait is used up on it. _13, Copilot: with an upload pending or the connection gone, the last song's delete handed focus to the upload's disabled file input, and focus stayed on `<body>`._ Fall back to a container with `tabIndex={-1}` (or the next control that is on), and test the hand-over with the target off.
- **Accessibility claims.** A wrapper class doesn't change the target size of the control inside it. _05: `min-h-11` on a wrapper left the range inputs short._ Measure the control itself.
- **A blanket style that reaches a library's elements.** A global rule (`* { … !important }` for reduced motion, a reset, a theme override) also hits elements a library draws and drives with inline styles, where the style is behaviour, not looks. _12: cutting every transition under `prefers-reduced-motion` cut alphaTab's beat-cursor glide, which lasts one beat, so the cursor jumped to the end of each beat as it began and pointed a beat ahead._ List what the library styles inline (cursor, scroll, highlight), exclude it, and test the library's element under the condition the rule applies to.
- **Requirements that come with the kind of feature.** Some features carry a WCAG success criterion of their own, met by design rather than by markup: shortcuts on single character keys (2.1.4: a way to turn them off or remap them), anything on a time limit (2.2.1), motion set off by interaction (2.3.3), a gesture that only works as a drag (2.5.7), content shown on hover or focus (1.4.13). _10: M, D, S, C and `?` acted wherever focus was outside a field and couldn't be turned off, so speech input could change playback; the input guard only covered typing._ When a unit adds one of these kinds, its Build note names the criterion and how it is met, and a test proves it (here, the per-device "Single-letter shortcuts" switch).

## 6. What is drawn: does the check look at what the user sees?

- **Wrapping that can't shrink the box.** `overflow-wrap: break-word` (`break-words`) breaks a long word only once it overflows, so it doesn't lower the min-content width; a flex or grid item's `min-width: auto` is that width, and the item then refuses to get narrower than its longest word. Making a paragraph a flex container (an icon beside the text) turns its text into such an item. _12, Copilot: a loop's name beside its "playing" icon ran 550 px out of the loop panel on every size, though `break-words` was on the paragraph._ For user text (names, titles) in a flex or grid item, use `wrap-anywhere` (or put the text in its own element with `min-w-0`), and test with the longest value the database takes and no spaces, measuring the text's own line boxes (a `Range`), not its element's box, which stays put while the text overflows it (`textSpillingOutOf` in `tests/e2e/designPage.ts`).
- **A label placed by its data, cut off at the drawing's edge.** Text in an SVG (or any clipped box) anchored at a position that follows the data fits until the data puts it next to an edge, on a date nobody tried. _17, Copilot: the heatmap names a month at the column of its first week; in the week a month begins that is the last column, 13 units from the edge, and "Nov" was cut off._ For every label whose position comes from data, test it at both ends of its range, and flip its anchor (or reserve the room) where it would run out.
- **A hidden stand-in measured instead of what shows.** A control drawn by something else (an `sr-only` file input inside a styled label, a native checkbox under a custom box, a select under a button) passes any check of its own styles: its focus outline, size or contrast are those of an invisible box. _12, Copilot: the focus-ring audit measured the upload's hidden file input, whose browser `auto` outline passed, so removing the label's ring would still have passed._ Measure the element that draws the state (the label, the box), fail a hidden control that has none, and prove the check bites by removing the visible styling once. A sibling of "Accessibility claims" above, which is the same miss the other way round (a wrapper measured instead of the control).

- **A live region that says the same thing twice.** A polite `role="status"` is read when its content changes; set to the text it already holds, nothing happens and the screen reader stays silent. _13 QA: M, a mouse click on Metronome, M again: the second "Metronome off" was never read._ Make each saying a change (`announcementText`: a no-break space on every other one), and test that two equal sayings differ in the DOM. The same goes for a region that arrives already holding its text: nothing changed after it was there, so it is often not read. _PR 31: "Saved “Verse”." was a `role="status"` inside a form that is keyed and mounts anew at every save, so each note was mounted with its text._ Keep the region mounted, empty, outside whatever remounts (`LoopSavedNote`, rendered by the form's caller), change only its text, and test that the element after the save is the element that was there before it.
- **A breakpoint mirrored in code in other units.** A media query in rem or em is measured against the browser's default font size, which a user can raise, not against 16 px; code that mirrors a CSS breakpoint in px (`matchMedia('(min-width: 1024px)')` beside Tailwind's `lg` at `64rem`) then disagrees with the classes at every width between the two. _12, Copilot: with a 20 px default font a 1100 px window drew the loop sheet while the code took it for the column, so the sheet started open and "Play loop" left it over the score._ Write the query in the stylesheet's own unit, check the two strings equal (not their px at 16), and test at a non-default font size (`stubWindow({ fontSize: 20 })`, and in e2e Chromium's `Page.setFontSizes`).

## 7. Hygiene (Review already catches these; keep checking)

Unchecked `{ data, error }` (test setup included: _09: cascade tests whose unchecked setup insert could have been refused would pass on the empty table_), one-page list reads, multi-step work that continues after a failed step, test teardown that swallows failures, listeners, timers and DOM left after `destroy()`, 1-based vs 0-based bars, anything that breaks AGENTS.md. Test locators that match by an attribute some other element can also carry (_12, Copilot: the e2e sheet header was `button[aria-controls]`, which an open "More" button inside the sheet matched too, so closing the sheet failed in strict mode_): find a control by its role and name, or by its place (`:scope > button`), and run the step in the state that adds the look-alike. Fixture and seed times written as "n days ago" in 24-hour steps (`Date.now() - n * DAY_MS`) land a calendar day early or late across a change of clocks, or when the script runs near midnight, so a row meant for one side of a period's first day can fall on the other (_17 Review: the seed's only session in "the month before" sat on its 30th day; seeded in the last hour of a day within a month of the clocks going back it was day 29, and `stats.spec.ts` had no period before to compare with_): keep such a row a day or two clear of any boundary a test counts on, or build it from local calendar days at noon (`noonOf` in `stats.spec.ts`).

## Design rules that prevent these

- One exported predicate per precondition, used by the action, its button and its keyboard shortcut.
- One owner per piece of shared state; writers go through it and respect its locks.
- Gesture and timing logic in pure modules that take the full event sequence, so tests can feed whole paths.
- Mutations of one item know about each other (shared `mutationKey`, field-scoped reconciliation), so a second control writing the same row is safe by default rather than by audit.
- Every async step re-checks that it is still current (generation counter, halt latch, disposed flag) before it acts.
